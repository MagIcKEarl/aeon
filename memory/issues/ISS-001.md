## Symptom

When run through the pi harness (`read-only` mode), token-pick produces quality score 1 with flags `["empty_output"]`. The health assessment: "No usable output produced; skill only emitted an interactive prompt with no analysis, draft, or findings." The captured output (stdout) is empty — the skill sends its picks via `./notify` but doesn't write substantive content to stdout.

## Root cause

The skill instructions only said "Send via `./notify`" for the notification steps and "Log to `memory/logs/`" for logging. As a `read-only` skill, it cannot write files, and the log is appended by the post-run step. The CLAUDE.md mandates that substantive findings must appear in stdout (the captured output) — `./notify` is a delivery channel, not a substitute. Without an explicit instruction to output substance to stdout, the agent's final message was empty.

Additionally, the curl commands used `$COINGECKO_API_KEY` on the command line (via `${COINGECKO_API_KEY:+-H "x-cg-demo-api-key: $COINGECKO_API_KEY"}`), which is blocked by the Bash permission layer when the key is set.

## Fix

1. Changed notification steps (6a, 6b) from "Send via `./notify`" to "Send via `./notify` and also write to stdout (captured output for health scoring)".
2. Added step 8: "Output substance to stdout (captured output)" — explicitly instructs the agent to echo the full notification body to stdout as its final message.
3. Replaced bare `$COINGECKO_API_KEY` curl headers with `./secretcurl` + `{COINGECKO_API_KEY}` placeholder pattern (matching token-movers), preventing Bash permission layer rejection when the key is set.
